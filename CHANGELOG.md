# Changelog

## Unreleased

### Changed

- `readwebform.__version__` is `0+unknown` when the package is run from a source tree that was never installed, instead of a hardcoded number that could be wrong
- README status updated from "proof of concept" to beta; SPEC.md option table now lists `--url-host`, `--upload-dir`, `--env-prefix`, `--no-launch-browser`, `--submit-label` and `--version`

### Added

- Real-browser tests (`tests/test_real_browser.py`, Chromium via Playwright, new `e2e` extra) and a CI job that runs them
- The publish workflow creates a GitHub Release with the changelog entry and the built distributions after uploading to PyPI

### Fixed

Found by running the CLI and server with hostile inputs:

- **A submission is no longer thrown away when `--envfile` cannot be written.** The envfile, `--url-file`, `--upload-dir`, `--cert` and `--key` paths are checked before the form is shown (exit code 3), and if the envfile write still fails afterwards the result is printed to stdout before exiting with code 3. Previously the user filled in the form and got a traceback and no output
- Start-up failures (port in use, privileged port, unresolvable or unassignable `--host`, invalid certificate, unwritable `--url-file`, non-UTF-8 HTML on stdin) print a one-line error instead of a traceback
- An empty `--host` is rejected; it used to bind every interface without the usual warning. Empty values for `--url-host`, `--envfile`, `--url-file`, `--upload-dir`, `--htmlfile`, `--cert`, `--key` and the size limits are rejected too (exit code 8) instead of being silently ignored
- `--field` and the Python API reject the reserved names `_cancel` and `_csrf_token`; a field called `_cancel` made every submission a cancellation
- `--url-host` must look like a host: whitespace, newlines and URL punctuation are rejected, and `[::1]` no longer produces `[[::1]]`
- When the timeout fired while an upload was still being saved, the files already written were left in the upload directory and never reported. The server now waits for a submission that is being handled before it returns
- Saving many files with the same name took quadratic time (4,000 files: 20 s, now 0.5 s)
- `Content-Length` must be ASCII digits; `+10`, `1_0` and non-ASCII digits are rejected with HTTP 400
- Tests that failed on a busy machine: the Ctrl+C test sent the signal after a fixed sleep rather than when the server was up, and the launcher exit-status test depended on a script finishing within one second. The timeout tests no longer assert narrow wall-clock windows and run in about a third of the time

## [0.4.0] - 2026-11-09

### Changed

- **Behaviour change:** on a desktop the CLI now opens the browser by default. Pass `--no-launch-browser`, or set `READWEBFORM_NO_BROWSER=1` to disable the automatic launch, to restore the 0.3.0 behaviour of only printing the URL. The browser is not opened when no desktop is detected (`CI`, `SSH_CONNECTION`/`SSH_TTY`, or no `DISPLAY`/`WAYLAND_DISPLAY` on Unix), when `--host` is not a loopback address, or when `--url-file` is given. `--launch-browser` still forces a launch. The Python API is unchanged (`launch_browser=False`)
- stderr now says when the browser is being opened and when the launch failed
- README examples quote field specs that contain `|`, `*` or spaces (the unquoted forms did not run in a shell) and lead with plain quoted labels instead of `+`-encoded ones

### Added

- `--submit-label <text>` and the `submit_label` API parameter
- `--version`
- When bound to all interfaces (`--host 0.0.0.0` or `::`) the printed URL and the `--url-file` contents use a best-effort guess of the machine's network address instead of the unroutable wildcard address; `--url-host <host>` (and `url_host=` in the API) overrides it
- `demo/record_demo.py`: the README GIF is now generated by a script (Playwright plus ffmpeg) instead of recorded by hand
- Published to PyPI: `pipx install readwebform` or `uvx readwebform`


## [0.3.0] - 2026-11-07

### Fixed

- Multipart parser truncated files and fields ending in CR/LF, treated boundary text inside a payload as a delimiter, rejected non-ASCII filenames with HTTP 400, and depended on the order of Content-Disposition parameters
- `<input type="file" multiple>` with more than one file returned HTTP 500
- `--print-env` and `--envfile` crashed on repeated fields (checkbox groups, multi-selects)
- A user form with `method="get"` kept submitting via GET and the submission was lost
- `value=` was ignored for every declarative field type except checkbox
- A negative `Content-Length` bypassed all size limits
- `--host ::1` (IPv6) could not bind
- The listening socket stayed open after a successful submission, so a fixed `--port` could not be reused in the same process
- A connection that never sent a request (or never completed the TLS handshake on an HTTPS port) blocked the single server thread until the timeout
- Several `FormServer` instances in one process overwrote each other's state
- A second submission arriving during shutdown could overwrite the first
- An empty temporary upload directory was created on every run and never removed
- `--title` was not shown on the page in CLI mode; CLI and API pages used different templates and the CLI cancel button was unstyled
- `accept=.pdf,.docx` (as documented) only accepted `.pdf`
- Backslashes in `--text` raised an error when the input was a complete HTML document
- A `<form>` inside an HTML comment, or a `>` inside a quoted attribute, confused the form rewriting
- Browser output could corrupt the JSON on stdout
- `--html ''` fell through to reading stdin
- Usage errors exited with code 2 instead of the documented 8
- The README Python upload example indexed `UploadedFile` like a dict
- `__version__` reported 0.1.0

### Added

- Field types `radio`, `hidden`, `tel`, `search`, `time`, `datetime-local`, `month`, `week`, `range`, `color`
- Field options `checked`, `readonly`, `disabled`, `autofocus`, `minlength`, `maxlength`; `value=` for select (`a|b` with `multiple`), radio and textarea
- `--upload-dir` to choose where uploads are saved
- `--env-prefix`; environment output for repeated fields (`NAME`, `NAME_COUNT`, `NAME_1..N`) and for uploaded files (`NAME_PATH`, `NAME_FILENAME`)
- `cert_file`, `key_file`, `url_file`, `upload_dir` parameters on `read_webform()`
- `Field.checked`, `Field.minlength`, `Field.maxlength`; `Field.value` accepts a list for multi-selects
- `--timeout` accepts fractional seconds
- JSON `files` entries include `size` and `content_type`
- ruff and pyright configuration; GitHub Actions test matrix

### Changed

- The server is now `http.server.ThreadingHTTPServer` based: one thread per connection with a socket timeout, TLS handshake on the connection thread, outcome recorded once under a lock, listener always closed on exit
- A submission arriving after the session has completed receives HTTP 410
- Ctrl+C exits with code 130 and prints the JSON failure envelope with `"error": "interrupted"`
- `--envfile` and `--print-env` can be combined; envfiles are created with mode `0600`
- Field names with characters outside `[A-Za-z0-9_]` are mapped to underscores in environment output instead of being skipped
- `FormResult.fields` values and `FormResult.files` values may be lists for repeated fields
- Exit codes 4 and 6 are documented as reserved; they were never returned
- `Content-Length` is required on POST

## [0.2.0] - 2025-01-13

### Added

- Cancel button for forms - allows users to explicitly abort form submission
  - Enabled by default in declarative forms
  - `--no-cancel-button` flag to disable
  - `--cancel-label <text>` to customize button text
  - Returns `{"success": false, "error": "cancelled"}` on cancellation
  - Exit code 7 for cancelled forms
- Python API: `add_cancel_button` and `cancel_label` parameters for `read_webform_fields()`
- Custom HTML forms can add cancel button with `<button type="submit" name="_cancel" value="1">Cancel</button>`
- `--url-file <path>` option to write the form URL to a file for scripting

### Changed

- Exit code 7 is now used for user cancellation (was previously invalid argument)
- Exit code 8 is now used for invalid argument

## [0.1.0] - 2025-01-10

### Added

- Initial release
- Serve custom HTML forms or generate from declarative field specifications
- JSON and environment variable output formats
- File upload support with configurable size limits
- CSRF protection and timeout management
- HTTPS support with user-provided certificates
- Python API (`read_webform`, `read_webform_fields`)
- Cross-platform browser launching
- Comprehensive test suite (150 tests)
